Posted on 2024-06-04 Edited on 2024-06-06 In 工具篇 , verilator

1. verilator介绍

Verilator 是一款开源的支持 Verilog 和 SystemVerilog 仿真工具。它能够将给定的电路设计翻译成 C++ 或者 SystemC 的库等中间文件，最后使用 C/C++ 编写激励测试，去调用前面生成的中间文件，由 C/C++ 编译器编译执行，来完成仿真。此外，它也具有静态分析verilog代码语法正确与否的功能。

verilator的工作原理

如下图所示,verilator是基于将.v转换为.cpp来进行仿真的:

  • 首先，Verilator 将 Verilog 代码中并行的各个逻辑部件以合适的顺序串行化为C/C++代码. 每个逻辑部件会被转化为C++语言中的类,并提供对应的接口和API.
  • 接着，我们需要使用 C/C++ 编写激励文件。Verilator 为我们提供了顶层模块输入/输出引脚的接口，使我们得以对顶层模块的输入信号赋值或读取其输出信号。与使用 Vivado 仿真不同的是，我们可以实时地输出一些调试信息；要查看波形图时，需要将波形图导出到文件,然后用gtkwave查看；
  • 最后，Verilator 会生成一个 Makefile 脚本，利用 GCC 等编译器将生成的 C/C++ 文件和我们编写的激励文件编译成成用于仿真的可执行文件。

2. verilator命令

verilator工具的编译命令:一键生成可执行文件

其中， 是需要仿真的 Verilog 文件，[options] 是一些编译选项，这里列出一些常用的编译选项：

  • –cc：指定将<verilog_file(s)>转化为 C++ 代码；
  • –exe ： 是用C++手动编写的tb文件,指定为顶层测试文件;
  • –build：直接编译生成目标文件,即可执行文件；
  • –trace：导出波形文件时需要添加此选项,开启波形追踪；
  • –top-module ：指定 Verilog 顶层模块；
  • –Mdir ：Verilator 在编译 Verilog 文件时，会生成一系列的中间文件和输出文件，这些文件用于后续的编译和链接过程。指定 –Mdir 选项可以将这些文件放到一个特定的目录中，以便于管理和组织.default是obj_dir,可以改名为别的
  • -CFLAGS ：指定一个 GCC 的编译选项；
  • -I ：可以指定一个包含路径,用于查找文件。 以上是一个使用全部常用参数的示例,执行上述命令后,即可在fzx_obj_dir中看到一个可执行文件Vtop_module.执行后可以在当前目录看到波形文件<wavefrom_name.gtk>.

自定义verilator工具编译命令

上一小节使用verilator编译时候,会自动生成一个Makefile文件用于指导编译,名为V<top_module>.mk.在使用verilator编译时,如果指定了--build选项就会自动基于该.mk文件使用make进行编译,并生成可执行文件V<top_module>.
有时候需要自定义更丰富复杂的编译命令,就不能使用--build选项,而是需要重写一个makefile文件,在其中include V<top_module>.mk,并添加其他规则然后手动使用make工具进行编译.

4. 如何编写verilator工具的tb.cpp

4.1 深入理解什么是testbench

4.1.1 testbench的结构

Testbench 由不可综合的 Verilog 代码组成，这些代码用于生成待测模块的输入，并验证待测模块的输出是否正确（是否符合预期）。下图展示了一个 Testbench 的基本架构。

  • 激励（Stimulus Block）是专门为待测模块生成的输入。我们需要尽可能产生全面的测试场景，包括合法的和不合法的。
  • 被测模块（Design Under Test, DUT）是我们编写的 Verilog 模块，Testbench 的主要目的就是对其进行验证，以确保在特定输入下其输出均与预期一致。
  • 输出校验（Output Checker）用于检查被测模块的输出是否符合预期。
  • `timescale 1ns / 1ps: 时间刻度 单位 / 精度

4.1.2 编写testbench激励

  1. 全局信号
  2. 初始化其他信号

  4. 产生激励方式(2):always块产生激励 适用于场景:(1)时钟驱动的激励:比如要求是第17个时钟上升沿后改变激励信号从001到100.(2)周期性激励.(3)复杂的时序逻辑:本质上就是把simulu.v模块也需要当成一个模块来写了,而不是单纯的简单写几个initial块可以解决的情况.

4.2 verilator工具的tb.cpp的激励架构

理解上一小节的内容之后,就会发现,tb.cpp有3种架构:

  1. 完全替代tb.v的作用.这样top_module就是top.v了.
  2. 保留tb.v,但是需要让tb.v的全局信号留出端口,tb.cpp只给这两个全局信号发激励,其余信号的激励由tb.v来管. 这样top_module就是tb_top.v了.好处是:tb.cpp容易知道现在的仿真时间是多少
  3. 完全保留tb.v,tb.cpp只需要m_contextp->timeInc(1)增加仿真时间就行.

hexo(三)写博客&发博客

Posted on 2024-06-02 Edited on 2024-07-13 In 工具篇 , hexo | 搭建静态博客

1. 发博客流程

  1. hexo new [options] title # 建立一个名为title.md文件
    • title.md的图片等附件
      • 如果配置了_config.yml中的default_layout参数则是默认会建立一个与title同名的文件夹用于存放title.md需要用到的.png等文件.(而且必须这样存放)
    • tilte.md的路径
      • title.md会放在根目录/source/_posts下,这里面存的就是要发出去的文章.可以根据分类在_posts下自由放置在比如”工具篇”的文件夹下,并不影响.
    • [options]
      • [options]主要只使用-p 或者 --path参数用来指示文件建立路径.
  2. 编辑title.md文件内容
  3. hexo generate # 生成静态网页文件
  4. hexo server # 启动本地端口预览
    • 默认本地预览端口
      • 默认端口为4000,访问网址http://localhost:4000/.
    • 设置本地预览端口
      • 有时候4000端口会被占据或者出错,这时候需要重设预览端口
      • $ hexo server -p 4001 # 可以重设端口为4001
  5. hexo deploy # 把静态文件部署在网页(github.io)上
  6. 其他
    • $ hexo g & hexo d可以连续执行两个命令
